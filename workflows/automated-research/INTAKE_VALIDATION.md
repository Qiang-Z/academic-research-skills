入口返回0只表示材料检查可继续或已有研究完成记录；不表示新课题已经验证。依赖测试中明确标记了缺包、版本不符和不完整元数据的受控模拟，未为测试安装软件。PDF/XLSX使用自编文件头/容器夹具，只验证“仍需实际读取”的提示，不能据此声称任意真实PDF/工作簿已解析。

真实衔接由宿主在材料检查后另行准备六步交付并执行固定案例程序。它证明新入口能与现有执行器衔接，不代表只给三个参数便能自动完成任意学科研究。衔接日志保留最初入口版本；最终入口另做完成态重查，记录各自源码摘要，不把早期输出冒充最新版本。

## 从走查改进的地方

| 发现 | 处理 |
|---|---|
| 已有六步接口要求助手先整理多份JSON，新手看不到材料盘点结果 | 新增三项输入入口；自动创建仓库外项目，生成中文检查页，最多给三项下一步；助手维护交接文件 |
| 文件、网址、库安装记录容易被当成阅读或执行成功 | 分开记录文本可用、表格预览、待获取、需解析工具、包元数据与实际功能验证；不产生自动已读证据或模型结果 |
| 追加论文后容易误认为已经更新已固定证据 | 明示补充材料未自动纳入evidence；已接受问题范围也不会改变；协议固定后拒绝新增输入 |
| 六步完成后，PDF/URL预览标签仍可能待处理 | 明确材料检查与研究状态独立，以宿主实际evidence范围核对，不为显示完成而修改阅读标签 |
| 长文件名截断可能丢失格式后缀 | 副本命名保留原扩展名；不覆盖同名材料，每条材料使用独立ID |
| 生成页仍有材料ID和英文阶段、Windows重查命令不一致 | 下一步用论文/数据及文件名或URL定位，阶段使用中文；Windows沿用已测解释器命令，复查保留前后记录 |
| 指南中仍有一处优先用旧init的导航 | 统一自定义新手先用start接收材料，再由advance接受交付；底层init保留维护者用途并区分退出码 |

新入口不修改稳定的 `research_pipeline.py`、历史Penguins档案或上游快照。此前30项编排回归属于原版本验证，继续保留，不重标成本次新增测试。八个模块完整 `runtime_tested` 仍为false。

## 维护者复跑

```powershell
py -3.12 -B -X utf8 scripts/test_start_research.py
```

测试使用新的系统临时目录，材料夹具明确为自编检查输入。用户自己的材料与运行档案默认在仓库外，不加入发布清单。核心检查不会联网、安装依赖或导入执行用户给出的程序；后续真实阅读与科研运行依照已有授权和具体方案实施。

当前验证限于所记录环境。CSV预览最多前1000行，文本仅检查开头至多65536字符；数据单元格值不写入检查页。完整性校验不提供跨进程文件事务或任意格式解析保证。模型、GPU、数据库/外部服务依赖，以及统计方法是否适合问题，都须在方案和实现确定后另行验证。
