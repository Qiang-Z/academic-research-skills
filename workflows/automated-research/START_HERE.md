# 带着自己的问题、论文和数据开始

[返回首页](../../README.md) · [可复制示例](EXAMPLES.md) · [六步流程](README.md) · [验证范围](VALIDATION.md)

你只需告诉助手：**想研究什么、有哪些论文、数据放在哪里。** 暂时缺一项也可以开始。助手会先盘点现有材料，给出最重要的缺口和下一步，再逐步推进研究。

## 直接发给助手

让能读取本仓库的助手打开工作区，复制下面这段并填上自己的材料：

```text
请按 workflows/automated-research/SKILL.md 带我开始一个自定义研究项目。
研究问题：写下我想比较或解释的问题。
论文：提供本地文件、网址或已读笔记；没有就写暂缺。
数据：提供本地文件或公开下载网址；没有就写暂缺。
请先使用通用新手入口检查材料和当前所需依赖，告诉我已有材料、缺口和最多三项下一步。
你负责项目目录、命令和交接文件，不要求我填写JSON或选择技能名称。
材料能读就继续读取；明确实际阅读范围，再确定最小研究方案。未知信息保留为待确认。
```

把“写下……”“提供……”替换成实际内容；也可直接复制[已填好的练习](EXAMPLES.md)。论文可以先提供摘要或笔记，但助手应保留这个阅读范围，不能当成全文已读。数据字典、单位或来源说明若已有，可一并说明位置。

第一轮应得到一份简短的中文检查结果，以及项目中生成的 `START_HERE.md`。**这份项目检查页与当前仓库使用指南同名，位置不同。** 它会列出收到的材料、当前缺口、环境检查和下一步。无需先安装整套科研工具。

## 自动检查到哪一步

| 你提供什么 | 入口会检查什么 | 接下来由助手完成什么 |
|---|---|---|
| 只有问题 | 建立独立项目，指出尚缺论文或数据 | 收窄问题，寻找或请求最少必要材料 |
| 本地TXT、Markdown | 是否存在、非空，开头至多65,536字符是否可按UTF-8读取 | 实际阅读，区分全文、摘要、笔记与片段 |
| CSV、TSV数据 | 最多前1,000行的列名、列数一致性、候选缺失数；尝试UTF-8与GB18030 | 确认编码、变量含义、样本单位和研究适用性；不自动删行或选目标列 |
| PDF、XLSX | 是否收到、PDF文件头或XLSX基本容器结构，相关可选解析包的安装元数据 | 实际读取；PDF扫描件可能需要OCR，Excel还需确认工作表与公式 |
| 论文或数据网址 | 登记链接，标为待获取 | 在已有授权和可用工具范围内实际获取、读取并记录失败 |
| 已明确需要的软件包 | 检查当前解释器中的安装元数据；可比较声明的确切版本 | 确认它确实必要，并做导入/功能验证后再运行实验 |

自动接收的单个本地文件上限为50MiB，保留原文件，并在项目中保存副本与摘要；更大文件或其他格式交给助手按需处理。检查页只展示结构信息，不输出数据单元格值。CSV缺失统计仅覆盖已检查的行，缺失标记还需根据数据字典确认。

入口本身只用Python标准库。PDF会提示可选的 `pypdf` 路径，XLSX会提示可选的 `openpyxl` 路径，也可以使用助手已有的阅读工具，或提供可复制文本/导出CSV。**检测到包的安装记录，不代表包能运行或文件已解析。** 模型、GPU和外部服务依赖要等方案选定后再查；本入口不联网、不安装软件，也不执行用户提供的程序。

若当前环境没有可用Python，助手可以先在对话中手工盘点材料，并明确“自动检查未运行”，再说明准备环境或提供可读文本的下一步。

## 材料齐了以后怎样继续

首次创建后，研究仍停在“明确问题”阶段。材料检查通过只说明可以开始阅读与定题；它不会替你选择预测变量、比较方法、统计检验或结果。

助手接着读取当前阶段需要的已有技能，确认研究范围、观测单位和停止条件，再按项目的 `NEXT.md` 推进六步。论文读过哪些部分、数据来源与许可、比较方案和运行环境都要留下记录。需要计算时，先固定数据、实际代码和配置，再执行实验与适合本题的核验。

项目中几个文件各有用途：

| 文件 | 用途 |
|---|---|
| `START_HERE.md` | 给你看的当前中文检查页与下一步 |
| `CHECKS.json` | 给助手读取的本次检查结果 |
| `intake.json`、`intake-checks/` | 材料登记与每次检查历史 |
| `materials/` | 已接收本地材料的副本 |
| `NEXT.md`、`state.json` | 六步研究的当前交接要求和状态 |

补材料后告诉助手“重新检查这个项目”。检查会追加历史，不改写已接受阶段，也不会自动推进研究。原材料或项目副本变化时保留旧目录，另开新运行；方案已经固定后新增材料、代码或依赖，也应另开运行，不手动改历史摘要。

材料预览状态与六步进度独立：宿主后来读过PDF或获取过链接，不会让这个离线检查器自动改成“已读”；应以 `evidence.json` 中实际记录的阅读范围为准。补充论文也不会自动进入已接受的证据集，改变来源或方案时另开运行。

## 想自己运行命令

在仓库根目录的PowerShell中使用 `py -3.12 -B -X utf8 scripts/start_research.py start`，后接问题和材料。省略 `--output` 时自动创建新的临时项目目录，终端会打印位置；长期项目可指定仓库外尚不存在的目录。[示例页](EXAMPLES.md)提供整段可运行命令。

- 返回 `0`：本次材料检查可进入阅读/定题，或已有流程完成记录；不等于研究结论已验证。
- 返回 `2`：项目和检查页已经建立，但材料、读取路径或声明的依赖仍需处理；看中文提示。
- 返回 `1`：调用或路径等出现错误；保留现有材料，按报错修正，不覆盖旧目录。

`check --run "项目目录"` 可重查；协议尚未接受时，还可附加 `--paper`、`--data` 和 `--require` 补登记。依赖仅接受包名或 `包名==确切版本`；普通用户不必自己维护这些参数，由助手根据当前需要填写。

已有[企鹅真实案例](../../examples/real-penguins/README.md)展示完整自定义流程，但这个通用入口只复用交接与检查方式，不将企鹅的模型、年份划分或缺失处理规则套到你的研究。
