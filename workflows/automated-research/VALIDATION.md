## 0.6.1 自定义真实课题补充验证

[企鹅案例](../../examples/real-penguins/VALIDATION.md)已通过真实custom六步，另有独立数值复算；两轮完整输入、产物、源码快照和日志随案例保存。新代码接受前固定、并发改写拒绝、旧接口兼容等30项回归通过，实际输出与哈希见[本轮记录](validation/custom-regression.json)；额外报告并发改写探针单列，不计入30项。

修复了两个实测缺口：自定义实现未被协议固定，以及验证后取摘要导致接受未验证字节。`protocol.code` 可选兼容旧材料，但未声明会显示 `not_bound`；阶段读取同一份字节，接受前复查变化。自定义通用验证范围仍为结构与引用完整性。下文24项记录属于0.6.0历史版本，保留其原始源码摘要，不冒充当前版本测试。

## 0.6.0 验证分为四项

| 项目 | 做了什么 | 支持的结论 |
|---|---|---|
| 默认真实案例 | 新运行目录中执行 Wine、另一实现重算预测/标准化参数/指标/区间、生成本次中文报告 | 内置固定 Wine 路线可执行；前三步复用材料，后三步本次计算/核验/模板生成 |
| 状态与故障测试 | 缺材料、输入/结果改变、缺产物、不可用来源引用、路径、失败/超时、假成功、恢复和预算 | 所测分支有明确退出码与状态，不把错误结果当完成 |
| 独立新手走查 | 新上下文代理按入口跑默认案例，再创建缺材料的鸢尾花课题 | 能找到入口；缺材料时停在问题阶段，无虚构结果；不代表真人可用性研究 |
| 来源与技能检查 | 十项热门候选的官方元数据与固定文件静态阅读；十个本地技能摘要；组合技能格式校验 | 路由与来源可追踪；不代表执行了热门项目完整工作流 |

最终24项集成与反例检查全部通过；最终命令走查的八次调用均得到预期退出码。恢复已完成流程未增加计算尝试，七份科学计算产物与此前真实 Wine 运行逐字节一致。

## 实际结果和记录

默认运行产生 810 条预测记录（178 个样本在多个划分/条件下重复出现），覆盖六个划分、三个条件。主划分的多数类、原始尺度5-NN、训练集标准化5-NN分别为18/45、31/45、45/45；标准化相对原始尺度的差为31.11个百分点，条件化配对分层95%区间为[20.00,44.44]个百分点。补充划分保留全部结果；不将主划分100%外推为未来正确率。

程序没有重新搜索论文。五条历史阅读记录保留原日期、版本和指定范围；未取得来源的候选、获取失败与未决项保留。报告从本次指标生成，不复制历史稿件或旧图充当本轮输出。

- [最终测试记录](validation/tests.json)：实际命令、退出码、全部测试输出和执行器/测试/路由摘要。失败与超时测试采用明确标记的受控注入，不声称真实网络服务故障。
- [最终命令走查](validation/cli.json)：实际 `doctor / demo / verify / advance / init / status`、状态、数值与历史科学产物逐字节比较。
- [本次生成的报告样例](validation/demo-report.md)：从最终实际运行中原样复制的模板报告。
- [独立新手记录](validation/new-user-walkthrough.json)：明确记录其执行版本；随后改动由最终测试和命令走查重验。

## 实际发现并修复的问题

| 问题 | 修复与核对 |
|---|---|
| 原六步主要是文字串联，缺统一恢复入口 | 增加阶段状态、输入/产物摘要、下一步提示和追加事件记录；完成步骤恢复时不重算 |
| 旧来源容易被误当成本次搜索 | 前三阶段标记 `reused`，记录新搜索数为0；报告写明旧阅读范围 |
| Python优化模式会关掉旧数值核验器的断言 | 新入口拒绝 `-O`/优化启动，子进程清理 `PYTHONOPTIMIZE`；不改旧程序造成历史摘要失效 |
| 有退出码0但没有真实产物仍可能误报 | 阶段读取实际文件并核验；受控假成功缺文件用例被拒绝 |
| 固定小预算不适合已有明确范围的课题 | 创建时可配置检索/来源上限；保存配置摘要，运行中不能原地放宽 |
| 重试成功后历史失败记录未被全部保护 | 独立审查真实复现“删除旧失败记录后仍通过”，现将各次尝试文件与自定义失败引用纳入检查，并补充删除/修改反例 |
| 新手容易把 `init=2` 解释为创建失败，把 `status=0` 解释为课题完成 | 使用说明区分命令退出码与项目状态；下一步写中文含义，由助手维护结构文件 |
| 系统换行转换可能改变发布摘要 | 根目录加入字节保留规则；发布时检查文件摘要及实际检出内容 |

保留[修复前21项检查](validation/tests-before-log-fix.json)和[独立发现记录](validation/review-finding.json)，不把早期通过结果包装成没有发现缺陷。自动结构校验不能证明语义、来源真实性或自定义实验确实执行；真实研究仍需要对应的阅读、运行与科学核验。

## 复跑测试

在仓库根目录运行：

```powershell
py -3.12 -B -X utf8 scripts/test_research_pipeline.py
```

测试仅向全新的系统临时目录写入夹具和运行产物。正常案例使用公开 Wine 数据；自定义接口用的是自编结构夹具，其 URL 与数值不作为真实研究证据。真实流程命令见[使用入口](README.md)。

本轮没有自动部署、付费 API 接入、跨领域实验验证、正式系统综述、外部科学审稿或投稿。没有执行新候选上游代码；八个模块完整 `runtime_tested` 均保持 false，实验模块历史未完成项继续单独记录。
