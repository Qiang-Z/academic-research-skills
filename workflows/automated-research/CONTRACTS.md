# 阶段交付接口

[使用入口](README.md) · [组合技能](SKILL.md)

这些文件由助手或接入程序维护；新手只需提供问题和材料。所有路径相对本次运行目录，使用正斜线，不允许绝对路径、`..` 或符号链接逃出目录。数据和产物必须是真实文件，`sha256` 是该文件字节的摘要。不要将示例占位符当作已经完成的记录。

每次 `advance` 使用当前文件的一份字节快照做验证，并在接受前再次核对是否变化；接受的摘要对应实际验证过的字节。验证期间有文件改写会失败，不把新写入但未验证的内容登记为已接受。改课题、数据、代码或已接受文件，请另开运行目录；未接受的当前阶段可补齐后重试。完整 JSON 字段以当前执行器的校验和 `NEXT.md` 为准。

## 1 · question.json

| 字段 | 内容 |
|---|---|
| `question` | 一个可回答的问题 |
| `scope` | 比较的范围，暂不回答什么 |
| `resources` | 当前真实可用材料与计算资源 |
| `stopping_condition` | 哪些证据/资源条件满足时结束本轮，何时判定无法继续 |

四项均为非空文字。`init` 只替用户登记题目，其余字段空白，等待读取材料或必要澄清后填写；不会预设已获得数据。

## 2 · evidence.json

- `mode`：`new`（本轮实际获取）或 `reused`（沿用已有记录）。混合来源时在每条的阅读范围说明哪些为旧记录，不能把整批宣称新读。
- `search_log`：实际检索列表，每条含 `query` 和 `status`；没有检索可为空，但在范围中说明材料来源。失败/限流要保留。
- `sources`：来源列表，每条含唯一 `id`、`url`、`version`、`checked_at`、`status`（`read` 或 `unavailable`）、`read_scope`、`locator`、`supports`、`does_not_support`。阅读范围写实际页/节，不把摘要写成全文；日期是本轮读取或明确沿用的原记录日期。
- `unresolved`：待补事项列表。

不可获取的记录可留在列表，但不能用于报告的已支持主张或作为已读数据来源。URL 存在、标题一致与句子得到支持是不同检查。编排器不自动联网验证 URL 的真实性，也不替代全文阅读。

## 3 · protocol.json

| 字段 | 内容 |
|---|---|
| `design` | 比较设计与目的 |
| `unit` | 独立分析单位，样本/人/组/运行等 |
| `conditions` | 全部计划比较条件的非空字符串列表 |
| `metrics` | 指标及方向的非空字符串列表 |
| `split_or_comparison` | 数据划分/配对/组间比较与选择规则 |
| `leakage_control` | 预处理拟合范围、隔离或适用的偏差控制 |
| `stopping_rule` | 运行上限和失败处理，不能跑到正结果才停 |
| `previous_results_known` | 布尔值，是否已知该方案的结果 |
| `data` | 数据文件列表：`path`、`sha256`、`source_id`、`license` |
| `code` | 可选代码/配置文件列表：`path`、`sha256`；新复现实例应登记实际使用的实现与模型配置 |

这里是通用宿主交接接口，不能替代具体研究的方法学设计。内置 Wine 使用已有原协议，不转换成这个通用接口，也不接受替换 CSV。

`code` 的路径、摘要及文件存在性在协议阶段检查，接受后与数据一起固定，后续 `advance` 和 `verify` 会拒绝修改。先保存协议、数据、代码与配置，运行 `advance` 确认协议已接受，再由宿主执行实验。代码清单不会触发自动执行，也不证明命令实际使用了这些文件。

为兼容旧交接，省略 `code` 或填空列表仍可接受，但 `state.json` 的协议阶段明确记录 `implementation_binding: not_bound`，`NEXT.md` 提示“未绑定实现”；这类运行没有自定义代码/配置的协议保护。非空清单记录为 `declared_code_hashes`，含义仅为声明文件的摘要已固定。实验的 `protocol_sha256` 随之绑定包含该清单的协议。

## 4 · experiment.json

`status` 必须为 `measured`；记录 `protocol_sha256`、实际 `command`、`environment`，以及 `artifacts` 和 `failures` 列表。每份产物包含唯一 `id`、`path`、`sha256`。字段内容来自实际运行，程序不会执行其中的命令文字。

`failures` 是实际失败记录文件的相对路径列表；没有失败填空列表。登记的记录必须存在并纳入阶段摘要，不能只写一句“曾失败”。相关 stdout、stderr 和其他失败产物也应登记为可追溯文件。内置 Wine 自动保留各次尝试的文件并核对。

没有运行、只有计划或模拟内容时不要填 `measured`。宿主需检查预定条件覆盖、日志内容、真实标签来源及输出意义，不能只看进程退出码。自动接口能核对文件与摘要，不能仅凭这些判断外部实验确实执行。

## 5 · analysis.json

包含 `unit`、`comparisons`（文字）、非空 `limitations` 列表和 `claims` 列表。

每条主张包含唯一 `id`、确切 `text`、`artifact_ids`、`source_ids` 和 `locator`。引用必须能对应实验产物和已读来源；定位需足以让另一人找到具体表/键/页。列出全部条件、分母、配对和未覆盖不确定性，由宿主针对本研究重新核算。

内置 Wine 使用另一程序重算全部 810 条预测记录和主要统计；通用接口只做结构与引用检查。外部研究如有独立核验程序，请把其真实日志与覆盖范围加入实验产物，不能借用 Wine 的“数值核验通过”标签。

## 6 · claims.json 与 REPORT.md

`claims.json` 包含与已接受分析一致的 `claims`，非空 `limitations` 列表、`review_status`（`host_reviewed` 或 `template_generated`）和非空 `review_scope`。`host_reviewed` 只表示宿主核对，不能当作独立同行评审；`template_generated` 表示按模板生成。

`REPORT.md` 包含每条主张的确切句子、方法、来源与限制。自动程序能检查是否漏掉登记的主张，不能识别所有未登记夸张句，宿主仍需阅读全文做语义核对。投稿标准、人工审阅和额外实验属于另行记录的后续工作。

## 预算与状态

执行器保存阶段状态、输入/产物/源码摘要和追加事件。每次子进程有有限超时，失败重试有上限；无法继续时显示原因。四次检索/八个来源是默认宿主首轮工作约定，不是完整检索方法或自动扣费额度。

初始化可以通过 `--max-searches N --max-sources N` 设定正整数预算。执行器检查登记数量是否超过该运行预算，但不能监控宿主实际发出了多少 API 请求。预算进入配置摘要，运行后不能原地改大。默认实验和分析各最多三次尝试、每次子进程超时 120 秒，失败后不会自行重试；保留故障记录后由 `advance` 发起下一次。

中断后先读状态和下一步文件；保留失败尝试。遇到锁文件提示时先确认旧进程是否仍在运行，不同时启动两个写入同一目录的进程，也不通过删除状态文件制造“完成”。
