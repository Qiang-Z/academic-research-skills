# 三张入门任务卡：实际走查与优化

日期：2026-10-22。[任务卡](../../../prompts/README.md) · [新手指南](../../GETTING_STARTED.md) · [机器记录](results.json) · [固定用例](cases.json)

**结论：三张卡都能从自带样例直接开始；信息不够时会先请用户补充。**本次先按旧卡实际作答 9 项，再修改卡面，并用新的代理上下文分别复测 12 项。所有报告保留实际输入、回答和卡片摘要，原始上游文件未改。

这里的“实际走查”是当前宿主按任务卡完成限定文字任务，不是自动脚本模拟输出，也不是真人新手研究。每张卡的同一阶段内，多个案例仍在同一上下文顺序执行；不据此推算成功率或跨模型稳定性。

## 发现的问题与已做修改

| 任务卡 | 基线实际观察 | 已实施的改进 |
|---|---|---|
| 读论文 | 能解释给定摘要并正确索取缺失材料；缺输入规则主要依赖助手自行判断，上游流程比首轮任务重 | 卡内补可直接复制的教学摘要，明确摘要范围、原文定位、空输入处理和简短回答；中文索引明确首轮不自动扩展检索/知识库 |
| 整理想法 | 已有兴趣时可给小问题，但第一轮过长；完全没方向时，固定三个候选会用示范场景代替真实需求 | 有具体兴趣才给 2–3 个同兴趣小问题，先短表再展开一个；只有宽泛意愿先问一个实际困难；用步骤、记录和不支持条件解释“最小验证” |
| 修改文字 | 能识别单位错误与过度结论，也能原样保留清楚的段落；“保留原意”和纠错之间有措辞歧义 | 明确先指出依据再修正单位/结论，并标出含义纠正；无法确认时待核实，原稿合适时允许不改；默认保留原稿语言 |

三张卡都补上“材料未填或仍是占位符时只请求最少输入”，禁止自动回填样例。默认样例是用户主动复制的练习入口，不能悄悄替代用户缺失的材料。

## 版本、环境和复做方式

基线对应已发布提交 [e8a286c](https://github.com/Qiang-Z/academic-research-skills/commit/e8a286c2594efd1cbacbf9f4268e61b0ed73e997)。三张基线卡的 Git 对象内容均与事前记录的 SHA256 相同；优化后卡片在复测起止保持同一摘要，具体值见 [results.json](results.json)。六份分项报告记录实际读取的技能与参考路径。

本次在 Windows 的 Codex 宿主中进行文字任务，Python 只用于文件、摘要和检查；没有联网检索、安装、训练、远程部署、接入知识库或访问私有研究数据。使用的是自编摘要、兴趣和测试段落，指标只用于文字与单位核对，没有重新验证底层实验。

复做时读取对应版本的卡片和路由，将 [cases.json](cases.json) 中的完整材料替换进卡片，保留其他要求；空输入用例须先移除卡内样例。按报告观察行为与证据，不要求模型逐字输出相同回答。三个 `0` 用例仅适用于优化后版本。

## 仍未覆盖

尚未实测真实新用户、真实网页会话、不可读 PDF、长论文、多学科、多语言稿件或多模型稳定性。R3 是在已有上下文中限制信息使用的模拟，不能证明文件能力真的不可用。少量自编文字足以暴露本次问题，但不支持普遍可用性或科研有效性结论；各模块完整 `runtime_tested` 仍为 false。
