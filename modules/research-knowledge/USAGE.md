# 科研知识管理 · 使用说明

[模块首页](README.md) · [技能中文索引](SKILL_INDEX.md) · [教学示例](examples/README.md)

先确定当前项目和需要回答的问题，再选择普通文件或已有知识库工作流。每个记录都应说明“它来自哪里、实际读到或运行了什么、支持怎样的结论、下一步是什么”。

## 1. 准备材料与写入范围

| 材料 | 需要明确 |
|---|---|
| 项目 | 项目 ID、研究问题、当前阶段、允许维护的根目录。 |
| 来源 | 文献/网页/代码/数据/项目笔记的身份、版本或日期、位置、已读范围。 |
| 实验与分析 | 协议、运行标识、产物清单、分析单位、失败/缺失、结果限制。 |
| 主张与决策 | 当前主张、证据编号、相反证据、允许措辞、取舍理由和未决问题。 |
| 接入情况 | 使用普通文件还是已绑定 vault；Zotero 是否真实可访问；哪些操作和输出已完成。 |

保留原始材料与定位，不用一段反复转述的 AI 总结替代来源。私人研究材料放在自己的项目目录，公开模板只保留空白字段和公开教学材料。

## 2. 路线 A：普通文件目录

无需安装或连接服务，可使用以下简化结构。它是本库教学约定，不是 ARIS 或 ClaudeScholar 的直接导入格式。

```text
project-notes/
  index.md
  sources/
  experiments/
  claims/
  decisions.md
  maintenance.md
```

1. 用 [项目导航](templates/project-index.md) 记录问题、材料入口、当前状态及下一项动作。
2. 用 [来源与证据](templates/source-evidence.md) 给每个来源分配稳定 ID，再对具体发现建立 Evidence ID。一个来源可以有多条证据，来源 ID 和证据 ID 不混用。
3. 用 [实验与分析日志](templates/experiment-analysis-log.md) 连接协议、输出与分析；记录原始产物是否随知识库保存，缺失时说明如何重新生成。
4. 用 [主张与决策台账](templates/claim-decision-log.md) 保存允许表述、不能外推的范围、反证及变更理由。
5. 用 [维护交接](templates/maintenance-handoff.md) 检查链接、ID、证据强度和未完成项，将过期记录标明并连接替代版本。

标题可以改，ID 保持稳定。相对链接应指向真实文件；移动文件后修复入链并记录旧位置。通用模板允许人工维护索引，但不要将它们直接放进上游受 helper 管理的派生区域。

已填写例子见 [plain-files/index.md](examples/plain-files/index.md)。它转录既有实验/分析验证文档，并写明没有附带原始运行目录；读者可依前模块说明复跑后新增自己的产物记录。

## 3. 路线 B：使用已配置的知识库工作流

| 选择 | 准备与执行顺序 | 成功应由什么证明 |
|---|---|---|
| ARIS Wiki | 读取对应宿主入口；核对 helper 实际路径和项目目录；从有限材料开始，再检查页面、关系、索引与日志。 | 实际输出和检查结果；没有 helper 时不能只因日志写了“完成”就登记导入成功。 |
| ClaudeScholar Obsidian | 确认 vault 与项目绑定；用 core 管理项目骨架；用 source-ingestion 登记来源；维护唯一注册表、Index 和 Daily。 | 实际项目目录、规范笔记、登记及可解析链接。 |
| Zotero → Obsidian | 在已绑定项目中选择真实条目；确认文献身份、阅读范围与附件可读性；建立唯一来源笔记和证据记录，再决定是否综合。 | Zotero 条目到笔记的真实对应、来源定位、Evidence ID 与产物位置。 |

接入前使用选定分支自己的参考文件；main 的 `.claude/project-memory/` 与 codex 的 `.codex/project-memory/` 不能互相覆盖。ARIS 的 `graph/edges.jsonl`、Scholar 的 `_system/registry.md` 与本模块普通文件索引承担不同职责，不建立相互矛盾的多份“唯一真相”。

先在自己的新项目或可回滚副本上完成一次有限任务，再记录实际环境和结果。迁移已有库时先盘点身份、路径和引用，保留旧记录与映射；归档和删除不是同一操作。当前没有运行这些上游集成，详见 [运行状态导航](../../docs/RUNTIME_STATUS.md)。

## 4. 证据如何进入主张

| 目前拥有的材料 | 可以记录 | 不能直接升级为 |
|---|---|---|
| 题名、摘要或网页占位 | 检索线索、待阅读任务、已有元数据 | 已全文核对的论文结论。 |
| 原论文已读段落 | 带章节/页码的发现及其限制 | 超出已读范围的通用结论。 |
| 实验原始产物与分析 | 条件、分析单位和假设明确的结果 | 未覆盖数据、训练条件或研究总体的效果。 |
| 项目总结/验证记录 | 对该记录的转述、待核对项及复跑入口 | 已亲自核查原始产物或得到独立复现。 |
| 模型审阅意见 | 实际审阅方式、范围、疑点和建议 | 原始证据、正式同行评审或证明通过。 |

每次升级主张，检查 Evidence ID 是否存在、来源是否足够、限制是否保留。发现冲突时补充冲突记录和决策，不悄悄覆盖旧结论。实验失败应记录失败条件；临时连接错误应记录发生时间与修复线索，不写成永久能力判定。公共路线见 [证据检查指南](../../docs/EVIDENCE_CHECKS.md)。

ARIS 的证明状态、Scholar 的 claim strength、本模板的 `evidence_state` 是不同字段体系。不得仅按相似词义复制状态；需要迁移时逐项建立映射，并将无法对应的状态保留为未决。

## 5. 可复制指令

### A. 整理普通文件知识库

```text
请先阅读 research-knowledge 模块索引，用普通 Markdown 整理我的项目材料。
项目问题：[填写]；材料位置：[填写]；允许写入目录：[填写]。
建立项目导航、来源记录、实验/分析日志、主张与决策台账、维护交接记录。
每项结论写明来源和证据编号、已读/已核对范围、允许措辞与限制。
未知字段留空并说明，不编造 DOI、Zotero ID、运行结果或审阅状态。
保留已有记录，新增或修订时说明原因；输出一份可追溯的变更摘要。
```

### B. 使用已经绑定的知识库

```text
请读取当前宿主对应的知识管理入口，仅维护项目：[项目 ID 与明确目录]。
已配置的知识库和来源访问方式：[填写]；本次任务：[导入/更新/检查]。
先确认项目绑定、既有结构与规范注册表，再处理指定材料：[填写]。
记录真实来源、阅读状态、Evidence ID、产物位置及未完成事项。
对链接和登记做实际检查；如果接入不可用，交付缺口与可保存的本地记录，
不得把占位笔记写成导入、全文阅读或同步成功。
```

### C. 交接给写作或审稿回复

```text
请从本项目知识库整理本轮交接：[材料范围]。
输出研究问题、当前主张、对应 Evidence ID、源文件定位、允许与禁止的措辞、
冲突/失败/缺失、上次决定及下一项证据需求。
只引用实际存在的材料；区分项目验证记录、原始运行产物与论文来源。
将需要重新核验的数字、引用和过期结论列入待办，不在交接时自动增强结论。
```

## 6. 交付前核对

- 项目边界清楚，来源 ID、Evidence ID、主张 ID 的含义和唯一性明确。
- 每条持久主张能回到材料和具体位置，转述、原文和自己的解释可区分。
- 缺失、矛盾、负结果和证据限制没有因摘要或迁移而消失。
- 链接可用，索引与所选系统注册表一致，派生视图没有被当作独立来源。
- 变更有日期和理由；过期记录有替代关系，交接包含未完成项。
- 文档检查、示例核对、真实接入与上游运行状态分开记录。
