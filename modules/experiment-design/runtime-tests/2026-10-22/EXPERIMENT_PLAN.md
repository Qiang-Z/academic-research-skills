# 实验计划：已公开教学案例的工程复跑验证

日期：2026-10-22。计划状态：已制定，等待新上下文审阅及执行。`AUTO_DEPLOY=false`。

本计划依据仓库内 ARIS Codex `experiment-plan` 的“主张—证据—运行顺序”结构制定，输入为本仓库原创的 [微型实验](../../examples/toy-reproducibility/README.md) 及其固定协议。该案例的历史结果已经公开。本次验证工程流程与产物一致性，不是盲测、正式前瞻预注册、新方法验证或论文复现。执行前记录本文件、消融计划、原始协议和两份示例代码的 SHA-256；执行中只追加运行记录，不依据结果改写验收标准。

## 问题与方法边界

教学任务使用 240 个合成样本及两个整数特征，`x0` 的符号决定原始标签，`x1` 为较大数值尺度的随机特征，另有固定随机过程产生的标签翻转。比较原始距离 1-NN、仅用训练集极差缩放的 1-NN，以及移除 `x0` 距离项的消融。没有参数训练、模型选择或调参。

实验入口固定为原有 `run_demo.py` 和 `verify_demo.py`。本次不修改原始示例，不运行上游 ARIS 代码，不启用 SSH、GPU、云端任务或自动部署，不安装依赖或读取凭据。运行产物位于本机新建临时目录；负例只改临时副本。

## 主张与最小证据

| ID | 本次要核查的有限主张 | 最小证据 | 不支持的主张 |
|---|---|---|---|
| C1 | 同一环境、原始代码和固定协议的两次独立完整运行可得到一致的协议、数据、划分、预测及指标 | 两次不同输出目录、两份运行日志；原验证器通过；三个业务产物逐字节一致；全部条件和种子保留 | 跨平台可复现、已复现某篇论文、上游完整工作流通过 |
| C2 | 该流程能检测指定的产物损坏、语义错误及不合法操作，并保留完整消融证据 | 五类预设负例的非零退出与错误内容；原始输出未受污染；独立实现复算全部预测、划分、极差及指标 | 对所有无效输入都安全、验证器没有缺陷、科学方法正确或真实世界有效 |

反主张：单次退出码为零、仅有摘要相同或仅有较高 accuracy，都不足以证明本次验证完成。性能未达到历史方向时仍保留全部结果；它触发调查，不触发删种子、改协议或追加搜索。

## 固定协议与数据使用

| 项目 | 固定值或规则 |
|---|---|
| 研究标识 | `toy-feature-scale-v1` |
| 数据种子 / 样本数 | `1729` / `240` |
| 标签翻转参数 | `label_flip_every=10`；随机过程，不保证实际恰好翻转 10% |
| 划分种子 | `11, 23, 47`，全部保留 |
| 每个划分 | 训练 144、验证 48、测试 48；三部分互斥且完整覆盖 |
| 条件 | `raw_1nn`、`scaled_1nn`、`scaled_1nn_without_x0` |
| 主记录指标 | 每个种子、条件、验证/测试集的 `n`、`correct`、`accuracy` 和逐样本预测 |
| 缩放与选择 | 极差只拟合训练集；验证集仅作诊断；无模型选择、超参数选择或提前停止 |
| 完整性 | 每次完整运行应有 3 种子 × 3 条件 × 2 评价集 × 48 = 864 条预测；两次合计 1728 条 |

两次完整运行均由入口一次性生成全部条件；入口不支持分别启动单个条件。本计划不虚构按条件启动的命令。不同划分来自同一份数据，样本可能重叠；三个种子不能当作三项独立研究，不做显著性、功效、置信区间或总体因果推断。

## 核心实验块

| 块 | 对应主张 / 目的 | 对照与指标 | 通过标准 | 失败解释与产物 |
|---|---|---|---|---|
| B1 环境与冻结 | C1：确认实际输入版本及可执行环境 | Python 版本、实现、平台；源文件和计划摘要 | 本机已有可用 Python；源文件与冻结值一致；无第三方包要求 | 缺少解释器记阻塞；记录环境、摘要，不把准备成功算作运行成功 |
| B2 两次完整复跑 | C1：同配置重新执行 | `run-a` 与 `run-b`；全部三个条件、三个种子、两个评价集 | 每次成功生成且只生成四个预期文件，内容覆盖 864 条预测；无漏条件 | 保存退出码、标准输出/错误及文件清单；失败时暂停结果解释 |
| B3 正向与独立核算 | C1/C2：核查正确性与一致性 | 原验证器；独立标准库核算；三个业务文件字节 | 原验证器通过；独立核算匹配每条预测、划分、训练极差、计数和 accuracy；业务字节相同 | 任一不符即记录缺陷，不能用另一检查通过抵消；保留全部差异 |
| B4 五类负例 | C2：错误能被识别 | 见下表，均来自新临时副本或不合法调用 | 指定操作非零退出，且错误理由与测试目的相符；原始产物不变 | 无报错、理由错误、污染原产物分别记录；不改源代码来使本轮通过 |
| B5 结果交接 | C1/C2：证据不越界 | 完整结果表、环境、日志、哈希、审阅记录 | 所有 MUST 项都有实际状态和证据；未执行项明确标注 | 只汇报实际完成范围，不将宿主适配或教学例算作上游训练链验证 |

核心证据表展示所有三个种子的验证及测试计数与 accuracy，同时保留较差条件。主表为完整性、一致性和错误识别结果；本次不制作论文主表、不声称新颖性，也不引入 LLM/VLM、强化学习或其他前沿组件。

## 必做负例

| ID | 操作 | 预期结果与附加检查 |
|---|---|---|
| N1 | 对已完成的 `run-a` 再次运行原入口，并指定同一个输出目录 | 非零退出，明确拒绝已有输出；前后四个文件摘要相同 |
| N2 | 验证时将同一目录同时作为待验证目录与 `--compare` | 非零退出，明确拒绝自比较；不得将它计为第二次独立复跑 |
| N3 | 完整复制 `run-a` 到新临时目录，只修改一条预测，保留旧产物摘要 | 非零退出，报告摘要不匹配；原始 `run-a` 不变 |
| N4 | 另复制 `run-a`，翻转一条预测的 0/1 值；同步按记录重算该评价单元的 `correct`/`accuracy`，再更新 `manifest.json` 内 `runs.json` 的 SHA-256 | 非零退出，报告重算预测与记录不符；不能仅依赖摘要或内部指标一致性放行 |
| N5 | 复制协议到临时目录，将 `split_seeds` 改为含重复种子的列表，其他字段不变；使用新输出目录运行 | 非零退出，明确拒绝重复种子；目标输出目录不存在；原协议摘要不变 |

负例的“通过”指错误成功被识别，不是被修改的数据通过验证。对所有负例记录完整命令、退出码、具体诊断、相关副本摘要及原始文件未改变的证据。未测输入类型不得外推为已覆盖。

## 运行顺序与停止规则

1. M0：完成新上下文审阅；记录审阅性质、意见和处置。检查本机解释器，冻结计划、消融表及原始输入摘要，创建唯一临时根路径名。
2. M1：执行 R001（完整 `run-a`），检查四文件清单与内容覆盖；失败即保留产物并停止后续成功推断。
3. M2：执行 R002（完整 `run-b`），要求输出路径不同；不得复制 R001 来充当 R002。
4. M3：执行 R003 原验证器比较和 R004 独立核算。独立核算不得导入示例的生成、拆分或预测函数；使用有理数距离等独立写法，并核查全部 864 条预测而非只看汇总。
5. M4：依次执行 R005—R009 对应 N1—N5。出现意外放行或意外错误时记录问题；未受影响的负例可继续，但相关主张保持不通过。
6. M5：完成 R010 汇总与交接。两次运行和所有条件都必须保留；无追加种子、数据规模或参数扫描。

上述均为 MUST；没有阻碍本轮完成的 nice-to-have 项。跨 Python/操作系统复跑、真实数据、GPU/远程训练和更广泛输入鲁棒性另立计划，不作为本轮通过条件。

在仓库根目录运行的核心命令如下。`$experimentTestRoot` 指向尚未使用的临时目录；不要先创建 `run-a` 或 `run-b`。

```powershell
$experimentTestRoot = Join-Path $env:TEMP ('ars-experiment-validation-' + [guid]::NewGuid().ToString('N'))
py -3.12 -B -X utf8 modules/experiment-design/examples/toy-reproducibility/run_demo.py --output (Join-Path $experimentTestRoot 'run-a')
py -3.12 -B -X utf8 modules/experiment-design/examples/toy-reproducibility/run_demo.py --output (Join-Path $experimentTestRoot 'run-b')
py -3.12 -B -X utf8 modules/experiment-design/examples/toy-reproducibility/verify_demo.py (Join-Path $experimentTestRoot 'run-a') --compare (Join-Path $experimentTestRoot 'run-b')
```

这是计划命令，不代表已经执行。若本机已有解释器名称不同，可替换入口调用并如实记录版本；不能宣称已测试未执行的环境。

## 资源预算、风险和验收清单

- 依赖：已有 Python 标准库、CPU、可写临时目录；PowerShell 用于本机命令、摘要和日志。无需 NumPy、PyTorch、CUDA、Hydra、DVC、W&B、网络、API 密钥、数据下载或包安装。
- 计算预算：GPU 为 0；串行执行两次完整样例，加验证、独立核算及五类负例。单个进程上限 120 秒，整组执行上限 10 分钟，均为事前限额，非实测耗时；超限记录并停止对应进程，不自动扩容。
- 数据和人工需求：仅合成数据；无需招募参与者。需要一次独立新上下文审阅；同模型家族审阅仍属临时性内部审阅，不能替代领域专家验证。
- 最大风险：原验证器复用原算法，重复同一种错误。以不导入示例函数的独立核算降低风险，仍不能外推真实研究有效性。
- 旧结果已知：本次冻结只能防止当前复跑中随意改方案，不能构成对已知结果的前瞻盲测。
