# 实验设计与复现 · 使用说明

[模块首页](README.md) · [技能中文索引](SKILL_INDEX.md) · [示例目录](examples/README.md)

这份说明帮助你把研究问题变成可执行、可追踪、可检查的计算实验。先读取 [技能索引](SKILL_INDEX.md)，按当前任务和宿主选择一个入口。源码已保存不代表技能已经安装，也不代表项目环境、数据、GPU 或外部连接已经准备完成。

## 1. 明确本轮要交付什么

| 本轮目标 | 可以交付 | 不能由此推定 |
|---|---|---|
| 仅设计实验 | 主张、基线、评价协议、消融与预算计划 | 代码已实现或结果已取得 |
| 准备实现并做最小检查 | 可审查的代码、配置、命令与检查日志 | 完整实验有效、论文结论得到支持 |
| 重跑已有代码 | 在记录的环境和输入下重新执行，比较产物 | 跨环境完全一致或完成独立实现 |
| 独立实现或论文复现 | 对齐目标设定，记录实现差异与结果偏差 | 只靠一次指标接近即可证明全部结论复现 |

先把目标论文、表格、设置或具体主张写清楚；若没有论文目标，就称为方法验证或教学复跑，不写成论文复现。容许偏差和判断方式在看结果前确定；未取得参考结果时标为待补，不虚构通过阈值。

## 2. 最少需要的输入

- **研究问题与假设：**要检验哪一条主张，以及什么结果会反驳它。
- **参考对象：**原论文版本、目标表格/指标、原实现或选定基线；没有则注明。
- **数据与评价：**来源、版本、划分、预处理、标签来源、指标定义和分析单位。
- **实现与环境：**代码版本、配置、依赖、目标机器及已知限制。
- **资源边界：**预算、时长、并行任务数、存储、运行与停止范围。
- **交付位置：**自己的研究项目目录；公开仓库只保留通用模板和教学材料。

## 3. 六步工作流

### 第一步：固定研究问题与复现目标

用 [实验计划模板](templates/experiment-plan.md) 把“想提升性能”写成可检验问题，关联文献或 idea 交接中的证据。定义主要指标、参考结果、评价条件、支持与反证条件；把参考文献事实、自己的假设和计划估计分开。

初次使用优先选 `experiment-plan`。如果只要计划，在指令中明确本轮不实现、不运行；不要直接启用完整的 `experiment-bridge` 自动部署路径。

### 第二步：锁定数据、代码与评价协议

填写 [复现检查表](templates/reproduction-checklist.md)。保留数据和划分的版本/摘要、预处理、代码提交或文件摘要、配置和环境信息；区分训练、验证、测试各自用途。调整方法或超参数使用事先规定的数据，避免依据最终测试结果反复选择最优配置。

记录种子及其控制对象，例如初始化、数据划分或采样。重复次数、随机性和硬件差异按任务说明，不能只写一个 seed 就宣称跨机器逐字节一致。实际命令和输出目录与对应配置一同保存。

### 第三步：设计基线、消融和运行顺序

用 [消融矩阵](templates/ablation-matrix.csv) 明确每个比较组改变什么、保持什么、回答什么问题。`ablation-planner` 可帮助安排删除/替换组件与敏感性实验，但没有主结果时仍是前瞻计划。

公平比较应说明数据、评价协议、训练与推理资源差异。建议先最小检查，再基线，再主方法，最后做能区分解释的消融。资源列中分别填写估计和实际值；预计指标不要放入结果列，也不因预算不足而隐藏失败运行。

### 第四步：准备实现并进行有限检查

确需实现时，按 `experiment-bridge` 读取计划并准备代码；将停留阶段和目标环境写进任务。若仅准备实现，明确 `AUTO_DEPLOY = false` 或等价的任务限制。准备好输入、输出、指标计算、错误退出和记录方式，再运行本次范围内的最小检查。

检查重点包括：输入是否正确、标签是否来自声明的来源、划分是否隔离、指标实现是否与定义一致、产物是否可读。小样本或短时运行通过记为“最小检查通过”，不记为“完整复现成功”。审阅不可用或仅本地检查时保留相应状态。

### 第五步：执行、监控与保留运行记录

只有当本轮任务包含实际运行时，才选 `run-experiment`，按已明确的环境、命令和资源范围执行。在 [运行日志](templates/run-log.csv) 中为每次尝试保留独立 Run ID，记录状态、版本、配置、数据、实际种子、结果路径和失败原因；重试或更改配置另建记录。

正在训练时可使用 `training-check`；收集任务状态和文件可参考 `monitor-experiment`。区分 `CONTINUE`、`WAIT`、`STOP` 的建议与实际动作，记录真正结束的任务标识及原因。日志不可达不等于训练失败；进程结束不等于结果正确。周期调度、远端同步、云资源和任务停止都按当前已授权范围处理。

### 第六步：复跑、核对并交接结果

按记录的命令重跑选定配置，把差异归到数据、环境、随机性、代码或评价条件；如需改变协议，记录新版本和原因，不覆盖旧结果。重新计算选定指标，并检查每个表格数字能否回到原始结果。

需要完整性审计时使用 `experiment-audit`，同时保留审阅方式、原始问题和未解决项。用 [结果交接模板](templates/results-handoff.md) 汇总运行覆盖、成功与失败、参考结果偏差、可支持的陈述和仍不能得出的结论。之后再做详细统计分析或论文写作；不得由退出码或审计标签直接推出方法优越性。

## 4. 可复制的自然语言指令

### A. 只整理实验计划

```text
请先读取本仓库 modules/experiment-design/SKILL_INDEX.md，选择当前宿主
对应的 experiment-plan 入口。
研究问题：[填写]；已有方法与证据：[填写材料]。
复现或验证目标：[论文版本、表格、设定或具体主张]。
数据与资源限制：[填写；未知则明确未知]。
本轮只交付实验计划、复现检查表和消融矩阵，不实现或运行实验。
请说明主张、替代解释、基线、评价协议、运行顺序、资源估计、支持与反证条件。
没有取得的结果、环境与依赖状态标为待确认，不填入预期实验数字。
输出到：[自己的研究项目目录]。
```

### B. 准备实现与最小检查

```text
请参考 experiment-design 模块中适合当前宿主的 experiment-bridge 入口，
按我提供的实验计划准备实现： [计划位置]。
已有代码和数据：[路径及版本]；本轮允许的执行环境与资源：[明确填写]。
本轮停在实现和已限定的最小检查阶段，不启动完整实验或云端部署。
请保留完整命令、配置、数据版本、代码版本、检查日志与输出位置。
检查失败时报告实际原因，不更改评价口径或把合成标签当作真实基准标签。
代码审阅方式及不可用项需明确记录；最小检查通过不标记为完整复现。
```

### C. 复核已有运行并准备结果交接

```text
请按 experiment-design 模块的复现检查表检查这批已存在的运行材料：
[日志、配置、原始结果、评价代码及参考结果位置]。
本轮先只读核对覆盖范围、版本、命令、失败运行和数值可追溯性。
请区分：未运行、运行失败、运行结束、指标已核对、参考结论仍待验证。
如发现需要重跑，先列出具体 Run ID、命令、资源和理由；本轮不自动重跑。
填写结果交接模板，保留偏差和未解决问题，不只展示最好的一次运行。
若没有实际完成独立审阅，不使用“审计通过”或“已独立复现”的表述。
```

这些指令可按实际授权范围调整；它们不要求斜杠命令已经安装，也不替代上游的宿主和依赖检查。

## 5. 从教学示例开始

先看 [自有 CPU 复现示例](examples/toy-reproducibility/README.md)。它是本仓库编写的 Python 标准库教学材料，使用合成数据演示配置、基线、对照、结果记录和复跑核对；它不调用上游 ARIS 技能，不需要云服务，也不是某篇论文的真实复现。

示例的实际运行命令、验证范围和已知限制以该目录 README 及 [模块验证记录](VALIDATION.md) 为准。即使自有示例检查通过，上游技能的 `runtime_tested` 仍为 `false`，不能将两个验证层次合并。

## 6. 交付前检查

本轮 [运行验证阶段快照](runtime-tests/2026-10-22/README.md) 已记录有限组件测试与监控演练，整轮验证尚未结束。CPU 示例使用标准库；JSON 队列清单也不需 PyYAML，YAML 输入需要另行准备。队列完整调度依赖 Linux/SSH、GPU、screen 等，当前 Windows 的第二次状态保存已有失败记录。请保留完整快照并检查任务编号唯一、输出内容有效、状态可再次保存；不要只复制旧 tools 包装入口，也不要把路径存在当成实验完成。完整依赖、失败与待测项以该快照及结果 JSON 为准。

- 研究目标和参考设置是否具体，未知项是否仍可见。
- 数据、划分、环境、代码、配置和命令能否定位到实际材料。
- 计划值、估计值、实测值是否分开；主结果和消融是否遵守声明的比较条件。
- 每次运行及重试是否有独立记录，失败和停止是否保留证据。
- 指标能否从原始产物重新计算；复跑差异和参考结果偏差是否说明。
- 本地检查、同家族审阅、外部审阅和独立复现是否准确标记。
- 输出是否保留不支持假设的结果，避免将教学例或小规模检查推广为科研结论。
