# 数据分析与统计 · 使用说明

[模块首页](README.md) · [技能中文索引](SKILL_INDEX.md) · [示例目录](examples/README.md)

先读取本模块索引，按当前问题选择一个必要入口。优先复用已保存快照和真实实验材料：先描述结果，再判断能否统计推断，最后决定允许怎样表述主张。上游文件保留原位；使用指南不等于已经安装或执行了这些工作流。

## 1. 从什么材料开始

最直接的上游输入是实验模块的 [结果交接](../experiment-design/templates/results-handoff.md)。至少核对以下材料；缺失项记录为待补，不能用猜测填满模板。

| 材料 | 需要明确的内容 |
|---|---|
| 问题与目标量 | 主要比较、主要指标、方向、单位；描述、预测或因果目标；要估计的是哪些对象和条件下的差异 |
| 设计与评价协议 | 数据来源/版本、训练与测试划分、基线配置、调参和模型选择过程、已知协议差异 |
| 原始结果与运行覆盖 | 可读取的逐样本/逐次运行产物、Run ID、成功/失败/停止/缺失记录；汇总表对应的源文件 |
| 分析单位与关联 | 样本、受试者、数据集、簇或运行中的哪一层才是独立单位；配对 ID、重复测量、交叉验证或共享数据关系 |
| 随机性与分析计划 | seed 分别控制什么；比较集合、异常值/缺失处理、区间或检验方法及选择时间 |
| 输出与环境 | 自己的研究项目目录、可用计算工具、所选分支和已执行/未执行的步骤 |

缺少逐条记录时可以整理已经核对的汇总值，但不要从均值和标准差反造数据。只有一条有效观测时，样本标准差不能填为零；区间、检验和效应量不适用时填写原因。失败运行也不能当作零指标、悄悄丢弃或混入成功运行的分母。

## 2. 六步工作流

### 第一步：固定问题与分析范围

填写 [分析计划](templates/analysis-plan.md)，记录主要指标、比较对象、目标量、分析单位、计划的比较集合和结论范围。如果已经看过结果，明确哪些分析是事后探索。不要反复改变指标、样本范围或单/双侧方向直到显著。

若只是整理结果，先选 ARIS `analyze-results`；若要正式的统计分析包，选 ClaudeScholar `results-analysis`。只有证据审阅需求时使用其只读审计模式。流程选择不自动启动实验、连接远端日志或写入知识库。

### 第二步：核对数据与可比较性

填写 [数据核对表](templates/data-audit.md)：核对列含义、缺失、重复、非有限数、指标范围、配置、评价集和来源。相同 ID 的两列是否确实来自同一对象，要由协议和记录确认；不能因为行数相同就视为配对。配对不完整时说明缺哪些对象及处理理由，不无声地只保留有利的完整对。

运行数、数据样本数、独立对象数、有效配对数和重采样次数分别记录。同一数据集的多个 seed、交叉验证折、同一对象的多次测量不会仅因占据不同表格行就成为独立样本。保留失败及缺失运行对比较范围的影响；没有日志时写“状态未知”，不猜测成功或失败。

### 第三步：先完成描述统计与数值复核

在 [分析结果表](templates/analysis-table.csv) 中记录实际观测、有效数、中心与离散程度、基线差值和来源。按任务选均值/标准差或中位数/分位数，始终标明计算对象及分母。需要按 seed 展示时逐个列出结果，并说明跨 seed 汇总仅描述这批运行。

先报告原始单位的差异；相对变化需注明公式、基线及指标方向。标准差、标准误和置信区间承担不同含义，不能统称“误差”；图中每条误差线也要写明含义。检查异常值来源，保留排除理由及敏感性分析，不为更漂亮的平均数删除运行。

### 第四步：有条件地进行推断

按下方方法表先判断独立、配对、层级或时间依赖，再结合目标量和分布特征选择方法。把效应估计、区间、检验假设、样本数、软件/参数及多重比较处理一起记录。未执行的方法写“未执行”；推断前提不足时保留描述与缺口，不输出虚构 p 值。

重采样也必须遵守设计。配对 bootstrap 应对两组使用相同索引以保留对应关系，而非分别抽样；记录重采样单位、次数、随机数设置、区间方法和条件范围。相关实现语义可查 [SciPy bootstrap 官方说明](https://docs.scipy.org/doc/scipy/reference/generated/scipy.stats.bootstrap.html)。引用这份资料不表示本模块示例调用了 SciPy。

### 第五步：将结果映射到有边界的主张

用 [主张—证据表](templates/claim-evidence.csv) 逐条记录拟写陈述、来源、允许措辞、禁止的更强措辞、限制及补证据动作。必要时用 `scientific-critical-thinking` 检查偏差与替代解释，再按可用宿主选择 `result-to-claim`。

“表中差值为正”“给定假设下区间/检验支持差异”“方法普遍更好”“机制已证明”需要不同证据。检验未拒绝零假设不能直接写成等效，单一设置中的差异也不能直接外推至所有数据集。保留审阅独立性和不可用状态；`verified` 数值存在检查不升级为科研结论已验证。

### 第六步：整理报告与下一步交接

先用 [报告提纲](templates/report-outline.md) 汇总方法、覆盖范围、真实结果、限制、失败、结论及来源。使用 `results-report` 完整流程前，应已有所需分析包及真实图表材料；若仍有阻塞，只交付缺口摘要和可核验结果，不把提纲称为已完成完整分析。

报告中说明每幅图回答什么、观察是什么、改变了什么判断；误差线与比较范围写在图注。补实验回到 [实验模块](../experiment-design/README.md)，文献依据不足回到 [文献模块](../literature-review/README.md)，写作只接收证据允许的措辞。保留分析命令、版本、输入输出位置及计划变更记录。

## 3. 选择轻量整理还是完整分析包

| 当前证据 | 可以先交付什么 | 暂不能声称什么 |
|---|---|---|
| 只有可核验汇总表 | 数据来源、描述性差值、缺失信息清单 | 不能补造逐样本数据、配对关系或显著性 |
| 有逐次运行结果，但 seed 的作用/运行依赖不清 | 逐次运行表、覆盖与散布、设计核对问题 | 不能自动用 seed 数作为独立样本数 |
| 有同一固定测试集上的成对预测及清晰协议 | 在该设置内的成对差值；满足相应前提时做条件性分析 | 不自动涵盖重新训练、换划分、换数据集的不确定性 |
| 有明确独立单位、适用设计及可追溯原始结果 | 有依据的效应估计、区间、检验、图表和统计附录 | 仍不能越过数据/设计范围作无条件主张 |

ARIS `analyze-results` 适合前端整理；它不会因为输出了均值与标准差就成为完整推断。ClaudeScholar `results-analysis` 的完整清单也不是强制每份数据都产生 p 值的理由：材料不足时选择审计模式，保留不适用和未执行项。

## 4. 统计方法选择简表

这是一张设计核对表，不是自动选法器。先明确目标差异与独立单位，再讨论分布、估计稳定性和检验假设；不按“样本量超过某个数”或一次正态性检验机械切换方法。

| 数据结构/问题 | 可考虑的分析方向 | 必须检查与说明 |
|---|---|---|
| 两个确实独立的组，目标是均值差 | 原始均值差与区间；适用条件下可考虑 Welch 两样本 t 检验 | 独立性来自抽样/设计；检查异常值和分布对估计的影响，不把不同数据集上的方法差异自动归因于方法 |
| 同一对象在两种条件下，目标是平均成对差 | 按真实配对 ID 计算差值；适用条件下考虑配对 t 或保留配对的重采样 | 配对依据、缺失对、差值分布、独立配对数；同一 seed 编号本身不证明对象相同 |
| 同一对象多次测量、对象属于簇、多个层级或时间相关 | 先按结构建模，或按有依据的独立簇/区块设计重采样；必要时另行制定分析方案 | 对象/簇 ID、层级、时间顺序及独立簇数；不能把所有行压平后当独立样本。本模块教学脚本不覆盖这些设计 |
| 多个方法、指标、数据集或事后筛选比较 | 先划定比较集合及主要/探索性分析，再选择与目的相符的多重比较方案 | 报告所有纳入比较及原始/调整后的结果；控制家族错误率与控制 FDR 是不同目标，不能只调整挑出的显著项 |
| 只有少数 seed，或多个划分共享原始数据 | 优先逐运行描述；明确训练随机性、划分变化和样本变化各自的贡献 | 不直接把 fold、seed 或“seed×样本”当独立重复；需要覆盖哪层不确定性，应回到设计确认 |

独立与配对比较、均值差及 Welch 方差处理的基本区分可参考 [NIST 两样本 t 检验说明](https://www.itl.nist.gov/div898/handbook/eda/section3/eda353.htm)。配对分析围绕对应对象的差异开展，是否可推断仍取决于真实设计与所用方法的前提。

多重比较应写明控制目标和依赖假设。例如 BH 对独立或一定正相关结构有相应 FDR 控制条件，BY 可处理更一般的依赖但更保守；具体含义见 [SciPy false_discovery_control 官方说明](https://docs.scipy.org/doc/scipy/reference/generated/scipy.stats.false_discovery_control.html)。不能把“已经校正”当作设计缺陷、指标选择或数据泄漏的补救。

上游方法参考包含简化决策树，保留它是为了忠实记录来源。使用时不要把未拒绝正态性当作已证明正态，也不要认为非参数方法没有假设。配对、独立和聚类问题不能靠更换检验名字消除；不能仅因技能给出固定重复次数建议就宣称统计功效充分。

## 5. 可复制的自然语言指令

### A. 先只读审计，不补造缺失统计

```text
请先读取本仓库 modules/data-analysis/SKILL_INDEX.md，使用适合当前宿主的
results-analysis 只读审计流程核对已有结果：[材料位置]。
研究问题与主要指标：[填写]；实验协议与原始产物：[填写]。
请确认分析单位、配对/重复测量、每个 seed 的作用、失败及缺失运行、主要比较集合。
只交付已能确认的描述、不可使用的统计、允许与禁止的主张措辞，以及需要补充的证据。
缺少原始样本、来源或配对依据时写清缺口，不猜填数据、p 值、区间或独立样本数。
本轮不运行新实验，不生成正式分析包或图表。
```

### B. 对明确范围内的真实数据完成分析

```text
请按 data-analysis 模块整理分析计划与数据核对表，再对以下真实材料完成分析：
[原始结果、运行记录、评价协议、数据版本和分析计划位置]。
目标量、主要比较、独立单位和配对依据：[明确填写；未知项请保留]。
允许的计算环境和输出目录：[填写]。
先报告逐运行覆盖与描述，再论证能做哪些效应估计、区间和检验。
按设计保留配对或层级；分别写明样本数、运行数、独立单位数和重采样次数。
保留失败/缺失、异常值处理、比较集合、实际命令与软件版本；解释每幅真实图的用途和误差线。
前提不足则停止相应推断并交付缺口，不为凑齐分析包添加未经执行的结果。
```

### C. 从分析包到内部总结和主张

```text
请读取 data-analysis 索引，并检查已有分析包：[位置]。
拟写主张：[填写]；实验轮次与内部报告目的：[填写]。
先核对 analysis-report、stats-appendix、figure-catalog、真实产物及来源是否齐全。
缺少关键证据时先交付缺口摘要；完整时再按 results-report 整理内部实验报告。
用主张—证据表区分数值观察、统计结论、可能解释和仍待验证的主张，保留负结果与限制。
若调用 result-to-claim，按实际审阅方式记录独立性及不可用状态，不把本地判断标成外部审阅。
输出到：[自己的研究项目目录]；后续实验或知识库写入按本轮明确范围处理。
```

这些指令可按任务调整，不要求斜杠命令已经安装；读取本地技能说明不会自动执行其脚本、调用远端服务或取得密钥。

## 6. 从原创教学示例开始

先看 [示例目录](examples/README.md) 和 [配对分析示例](examples/paired-analysis/README.md)。示例使用 Python 标准库，后处理实验模块原创合成数据实验的结果，不调用上游技能，也不把教学数据当作论文或真实基准证据。

示例按 seed/划分描述已有运行，不把跨 seed 结果自动视为独立样本。固定 split 内的配对 bootstrap 用于展示配对和条件性重采样；即使产生了区间，也不代表换训练集、重新训练、换划分或目标总体的全部不确定性，更不支持方法普遍优越的结论。实际命令、输入要求、输出和限制以示例 README 为准。

自有示例的运行检查与上游工作流验证分开记录在 [VALIDATION.md](VALIDATION.md)。检查通过的范围以实际记录为准，上游 `runtime_tested` 仍为 `false`。

## 7. 交付前核对

- 数字能否回到原始产物、评价定义和实际运行；缺失、失败、排除与分母是否可见。
- 目标量、分析单位、配对/层级、seed 的作用及比较集合是否明确。
- 描述、推断、解释和主张是否分开；不适用和未执行项是否有理由。
- 差值、单位、效应量、区间/误差线含义及方法假设是否写清楚。
- 结果是否涵盖声明范围内的全部比较，是否保留探索性分析及计划变更。
- 主张是否有允许措辞、不能外推的范围、审阅状态和下一步证据需求。
