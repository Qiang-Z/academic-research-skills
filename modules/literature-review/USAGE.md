# 文献检索与综述 · 使用说明

[模块首页](README.md) · [技能中文索引](SKILL_INDEX.md) · [五篇论文示例](examples/rag-literature-walkthrough.md)

这份说明提供一条从研究问题到文献综合的中文使用路径。技能源码通过相对链接复用现有快照；本模块不自动安装技能、不注册斜杠命令、不配置参考管理器。以下通用指令是自然语言示例；已经执行的命令、依赖和结果另见 [2026-10-22 实测报告](runtime-tests/2026-10-22/README.md)。当前已确认部分路径可运行，也发现参数不匹配、静默失败和环境依赖问题。

## 1. 先明确要做哪一种综述

| 任务 | 合适目标 | 应保存的记录 | 不能据此声称 |
|---|---|---|---|
| 快速梳理 | 看懂手头 3–5 篇论文、建立术语和待读清单 | 文献身份、实际阅读范围、相关性与疑问 | 领域已经搜全、全文已读完、存在确定创新空白 |
| 专题综述 | 按问题或方法比较一批文献，形成有来源的主题综合 | 检索日志、选择理由、精读笔记、证据矩阵、局限 | 仅凭精选文献就满足系统综述要求 |
| 系统综述 | 按预先制定的方法收集、筛选、评价并综合证据 | 问题与协议、可重现检索、记录/报告/研究对应关系、筛选理由、全文评价、审阅分工与限制 | 仅用网页前若干结果或模型筛选就证明完整覆盖 |

本模块的五篇论文示例属于**限定材料的快速梳理教学示例**。如果研究目标是正式系统综述，应从 K-Dense 的流程参考制定方案，补齐适用方法、独立筛选及偏倚/质量评价；该示例不是完整系统综述。Meta 分析的统计计算另需专门工具和方法。

## 2. 准备最少输入

开始前用普通文本写清以下信息；不知道的部分标为“待确定”，不要由模型补成已知事实。

- **研究问题：**希望比较什么对象、方法、现象或结果。
- **范围：**年份、学科、语言、论文类型及是否纳入预印本。
- **已有材料：**论文链接或指定本地目录；区分元数据、摘要、全文和个人笔记。
- **来源与运行范围：**仅处理已提供材料，还是允许联网补充；需要哪几个来源；不把未连接的服务计入覆盖。
- **交付目标：**候选清单、精读笔记、证据矩阵、综述草稿或 idea 交接包。
- **输出位置：**自己的研究项目目录。公开仓库保留通用模板和公开教学示例，不承载未公开论文、私有笔记或研究数据。

## 3. 六步完成一个有限任务

### 第一步：界定问题与检索方案

用 [检索日志模板](templates/search-log.md) 记录研究问题、关键词与同义词、拟用来源、日期范围、纳排标准和每源限制。区分“拟执行检索式”与“实际执行记录”。

默认从 [技能索引](SKILL_INDEX.md) 中的 ARIS `research-lit` 入门；需要明确的多来源候选清单时，参考 ResearchStudio `paper-search`。

### 第二步：收集并去重

保留原始候选记录，再按 DOI、arXiv ID、规范化标题等识别重复记录；把预印本与正式版关联起来，不任意删除版本差异。记录实际贡献结果的来源，以及超时、缺失摘要、未检索或未配置的来源。

模型记忆中的论文只能加入“待核验线索”；确认官方记录后才进入已核验候选集。来源返回 0 条与来源请求失败应分别记录。ResearchStudio 上游脚本的 JSON 设计可用于保留未筛选记录，但本模块不要求自动运行该脚本。

### 第三步：初筛与精读

为每篇保留“纳入 / 排除 / 待确认”及原因。只有标题或摘要时，不推断完整方法、数据细节、负面结果或统计显著性。

选核心论文后填写 [论文笔记模板](templates/paper-note.md)，明确读过的版本和章节。对可复用论点补充页码、章节、表格、图号或其他可核对位置，并区分“作者报告”“从原文核对”“本项目解释”。

### 第四步：提取与比较

把笔记整理进 [证据矩阵模板](templates/evidence-matrix.csv)。相同指标名称不意味着可直接比较；数据集、划分、实验预算、评价协议和结果来源不同的记录，应标明不可直接横向排序或仍待核对。

按机制、研究问题和证据条件分类，保留不支持预期、相互矛盾与材料缺失的记录。证据不足时，输出待补读清单，不为了表格完整而补写实验数字。

### 第五步：综合与引用核验

按 [综述提纲模板](templates/review-outline.md) 形成“主题 → 共同点与分歧 → 支持证据 → 限制”的结构。引用每条关键论点时，同时核对：文献身份正确、引用版本明确、原文支持该表述。

只有摘要时，可以写“摘要中报告/描述了……”，并保留范围标签；不能据此建立已经通过全文证据审查的正式综合结论。ClaudeScholar 知识库流程要求的证据升级条件仍需满足，教学示例的摘要梳理不自动进入 `Knowledge/` 或 `Writing/`。

### 第六步：交接给创新点探索

填写 [idea 交接模板](templates/idea-handoff.md)，列出研究问题、最接近的已有工作、来源与证据位置、待解决问题、下一次检索和可能的最小验证。转到 [idea 模块](../idea-discovery/SKILL_INDEX.md) 时，把这些材料一起交给所选技能。

使用“在本次检索和阅读范围内尚未找到充分证据”这类范围明确的表述；不要将有限检索直接升级为“首次提出”或“无人研究”。

## 4. 可以直接改写使用的指令

### A. 只阅读手头五篇论文

```text
请先阅读本仓库 modules/literature-review/SKILL_INDEX.md，选择与当前宿主
对应的 ARIS research-lit 入口，处理我指定的 5 篇论文。
研究问题：[填写问题]。
材料：[填写文件或论文链接]。本轮只处理我指定的材料，不自动扩大检索。
请逐篇记录标题、作者、年份、版本、链接和实际阅读范围；只有摘要时明确注明。
按本模块模板输出论文笔记、证据矩阵、主题比较和待补读问题。
方法细节与数字只从实际可读的材料提取；不能读取的部分标为待核对。
先报告当前可用的读取方式与任务边界，不安装依赖或修改全局配置。
```

### B. 联网补充一个专题的候选文献

```text
请参考 modules/literature-review/SKILL_INDEX.md 中的 paper-search 入口，
为问题 [填写问题] 制定并执行可用来源上的文献检索。
年份范围：[起年—止年]；来源：[明确来源]；每来源初始上限：[数量]。
请保留实际检索词、执行日期、来源、原始候选记录、去重数、筛选理由和失败来源。
如果入口依赖的脚本或连接未准备好，说明缺口；不要把它写成已执行。
模型记忆只能作为待核验线索。请核对候选的官方文献记录后给出精读顺序，
不把引用次数或检索排序当作证据质量，也不声称本次覆盖完整。
输出保存到：[自己的研究项目目录]。
```

### C. 从已有笔记形成专题综述

```text
请参考 modules/literature-review/SKILL_INDEX.md 中 K-Dense literature-review
的流程，使用我提供的检索日志、论文笔记和证据矩阵，写一份专题综述草稿。
问题：[填写问题]；材料：[填写路径]；输出位置：[自己的研究项目目录]。
按主题比较研究问题、方法、证据和限制，区分作者主张与本项目解释。
每个关键结论关联来源记录及原文位置；未验证的引用和只有摘要的材料单独标记。
请列出证据冲突、覆盖限制和下一步补读任务，并填写 idea 交接模板。
本轮是专题综述，不将其标成已完成的系统综述，不开展 Meta 分析计算。
```

## 5. 环境与文件约定

| 使用层次 | 需要什么 | 本模块当前状态 |
|---|---|---|
| 阅读索引、填写模板 | Markdown/CSV 阅读编辑能力 | 文件已整理；无需联网或安装上游 |
| 分析已提供论文 | 宿主可访问指定材料，具备所需解析能力 | 具体 PDF/格式能力需在使用时确认 |
| 实时文献检索或引用核验 | 可用网络、来源接口及相应工具 | 宿主官方网页路径已执行；原始脚本分项成功或失败，见实测报告 |
| Zotero/Obsidian 联动 | 已有项目、正确目录与宿主连接 | 未连接真实服务；只测试临时合成绑定的部分构图组件 |
| PDF 导出或 AI 示意图 | Pandoc/XeLaTeX 或额外图像服务 | PDF 原样运行因缺程序失败；AI 服务未调用 |

按宿主选择入口，主版本与 Codex 版本分别查阅。上游文档出现的斜杠命令、环境变量或工具名不能证明当前宿主已具备相应能力。本文指令采用自然语言，避免把“读到了技能文件”混同为“安装和配置完成”。

## 6. 结束时检查什么

- 检索范围、日期、实际使用来源及失败项是否可见；拟执行步骤有没有被误写成已执行。
- 文献身份与版本是否可追溯；模型回忆、摘要阅读和全文证据是否清楚区分。
- 排除记录及原因是否保留；系统综述的记录、报告、研究数量是否分开且能对应。
- 关键论点能否找到支持位置；无来源数字、未验证引用或推测是否仍有明确标记。
- 综合是否展示分歧与局限；idea 交接是否保留检索范围和待验证条件。
- 若实际运行技能，是否另外记录日期、宿主、版本、输入范围、成功/失败与限制。

早期文档整理和教学示例不构成上游运行验证。示例的来源核对范围见 [示例自身说明](examples/rag-literature-walkthrough.md)；最新真实执行范围见 [运行报告](runtime-tests/2026-10-22/README.md)。

## 7. 按实测结果选择运行路径

先用宿主网页能力运行一次有限任务：读取 ARIS Codex 入口，显式选择 `sources: web`、少量公开论文与摘要级范围，保存检索词、候选、筛选理由、指定版本页及综合。网络脚本失败时保留错误后改用可用网页入口；网页降级不计为原始脚本成功。[实际例子](runtime-tests/2026-10-22/synthesis.md) 展示本轮产物。

需要脚本时，在自己的项目环境准备依赖，使用原快照的明确路径；当前机器的临时依赖不等于你的环境已经安装。Windows 优先明确选择实际 Python 解释器，不能照抄上游 Bash 环境变量。各来源报告保存了本次命令与版本。

| 路径 | 实测后需要注意的事项 | 运行详情 |
|---|---|---|
| ARIS arXiv helper | 标准库即可启动；本次 Python HTTPS 请求失败而 curl 成功。指定 `vN` 会被辅助程序去掉，必须额外核对官方版本页 | [ARIS](runtime-tests/2026-10-22/aris-report.md) |
| ResearchStudio 检索 | 需 `requests`，OpenReview 另需 `openreview-py`；文档中的 `--json` 并不存在。聚合退出 0 也可能所有来源都失败，检查来源错误和实际记录 | [ResearchStudio](runtime-tests/2026-10-22/researchstudio-report.md) |
| K-Dense 记录处理与引用检查 | 记录处理是本地去重/筛选/导出，不能当作联网检索；DOI 验证需 `requests`。DOI 能解析与元数据匹配分开判断；不能把 Crossref 无记录等同假引用 | [K-Dense](runtime-tests/2026-10-22/kdense-report.md) |
| ClaudeScholar 引用/构图 | 指南式官方来源核对可执行；脚本及临时知识库组件另有缺陷和依赖，按报告使用。临时文件构图不证明真实 Obsidian/Zotero 联动 | [ClaudeScholar](runtime-tests/2026-10-22/claudescholar-report.md) |

检查产物中的有效记录、错误字段、元数据与内容支持，不能只看退出码或文件是否存在。需要固定版本、正式系统综述或全文证据时，先补齐对应输入与检查；不要把本次摘要级测试推广为完整自动化已可用。
